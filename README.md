新增原生回归测试 `node test/native-compaction.mjs`（需安装 DSH Desktop，可用 `DSH_TEST_EXECUTABLE` 指定路径），启用实际的 token meter 与 compaction-basic，覆盖已有图片及长聊天历史的继续修改、模型切换、失败重试和聊天模型恢复。测试使用隔离临时附件目录、假密钥及模拟 HTTP，不访问收费接口或真实会话。

2026-11-10 将 1.6.1 本地包通过 DSH 管理器安装并启用，在桌面真实对话中完成两次低画质 API 调用：2.6 Flare 生成 1536×864 的蓝色鲸鱼（约 13 秒），点击其“继续修改”并切换至 2.6 Sunburst 后生成 864×1536 的橙色鲸鱼及红帽（约 22 秒）。核对了真实 PNG 宽高、原图附件 ID 与编辑参考关系、两轮完成状态和 DeepSeek 聊天模型恢复；未自动重试，也未修改系统代理。已安装副本另通过含 compaction-basic 的隔离原生回归测试。版本对比显示正常，完整退出并重启 DSH 后，两张图片、模型、画质、尺寸与参考版本关系均正常恢复。

### 失败后重新编辑与重试（1.6.0）

- 失败、取消或中断的图片卡片提供 **重新编辑** 和 **按原参数重试**。重新编辑会恢复提示词、按原顺序排列的参考图、模型、画质、尺寸及原来的尺寸选择模式，点击本身不生成图片；输入框已有草稿或附件时先确认是否替换。
- 按原参数重试只提交一次新请求，保持原来的有效模型、画质、像素尺寸和参考图顺序，不改变输入框现有草稿。完成后恢复聊天模型，原失败记录保留。重试可能产生新的 API 用量；没有自动重试或模型回退。
- 新请求在调用接口前把恢复信息写入 DSH 会话，失败后或重启后仍可恢复；不记录 API Key、代理配置或临时图片地址。参考图缺失时会指出序号，不会静默丢图或改为纯文字生图。
- 旧版本失败记录仅从对应工具调用及之前的消息恢复。无法确认的参数显示为未记录，需要重新编辑并补全，不使用今天的默认参数冒充原参数。没有原参考图的历史记录仍需补充图片。
- 该功能简化失败后的操作，不修复公司代理到 OpenAI 的连接问题。

### 图片状态卡与版本对比（1.4.0）

- 开始执行生图或改图工具时，对话正文显示状态卡；完成后原位显示图片。失败、取消或进程中断后显示对应状态，不自动重试。
- 图片卡片列出生成时的模型、画质和实际像素尺寸，尺寸与请求不同时明确提示。新结果通过 DSH 原生工具展示元数据保存这些信息和参考图关系；历史结果尽量从原有文本恢复，缺失信息显示“未记录”。
- 点击 **对比版本**，从下拉菜单选择当前对话中已加载的另一张成功图片，并排查看；窄窗口自动上下排列。存在可识别的参考版本时，默认优先与参考版本对比。
- 在对比的任一图片下点击 **继续修改**，以选中的版本作为参考图，保留已有描述和非图片附件。点击本身不会调用 API；确认画图栏的模型、画质、尺寸并发送才会产生请求。旧图不会被覆盖。
- 版本编号按当前已加载图片的顺序显示，包括对话中的独立创作。向上加载历史后会补充更早的图片；“参考版本”单独标识可确认的编辑关系。对比列表不跨对话共享。
- 本轮不启用渐进预览，不添加流式预览请求或自动重试。

### 一次性画图（推荐）

1. 点击输入框旁的 **🎨 画图**，出现 **本次画图** 提示。
2. 在画图栏确认 **生图模型、画质、尺寸**，再输入描述并发送。没有附图时生成新图片，不会自动使用历史图片。
3. 图片生成完毕后继续正常聊天，不需要切换模型。

上传 PNG、JPEG 或 WebP 图片后点击 **画图**，输入修改要求即可编辑。参考图显示在原生附件栏，提示区显示本次参考图数量；可逐张移除，也可 **清空参考图** 重新创作。支持最多 16 张参考图。画图进行中使用 DSH 原生停止按钮取消；不会自动重试。

在对话中的任意图片下方点击 **继续修改**，该图片会成为本次参考图，替换输入框里原有的图片参考，已有文字保留。输入修改要求并发送即可；旧结果仍保留在聊天记录中。新上传的图也可以通过这个入口再次编辑。

**取消画图** 只退出本次模式，保留输入文字和附件。首次使用从插件读取 `defaultModel`、`quality`、`size`，之后在当前浏览器按对话记住你选择的参数。选择仅影响画图，不改变聊天模型或其他对话的默认值。每次发送把显示的三个参数固定到该次请求中；编辑也使用所选尺寸，不再悄悄按参考图方向改变尺寸。生成结果会再次列出实际模型、画质和尺寸。

尺寸默认 **跟随描述中的尺寸/比例**，输入“16:9 海报”“画幅 9:16”“生成 2048×1152 像素”等，面板即时显示将请求的尺寸。没有识别到尺寸时使用所显示的默认值。也可在尺寸菜单中选择预设或 **自定义像素**；手动尺寸优先于描述，面板会明确标注。描述有多个冲突尺寸时请手动选择，不会猜测。

GPT Image 2.5 支持自定义尺寸，但宽高必须为 16 的倍数、最长边不超过 3840、宽高比介于 1:3 与 3:1、总像素 655360–8294400。常见 16:9 默认请求 1536×864，也可选 2048×1152。**1920×1080 无法原生输出，因为 1080 不是 16 的倍数**；插件会在请求前提示，不静默取近似尺寸或改用更贵模型。高于 2K 的尺寸属于实验性输出。Mini 仍限于三种标准尺寸。结果使用 PNG 的真实像素尺寸；接口返回不符时会提示并保留图片，不自动付费重试。限制核对于 [OpenAI 图片生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate)与[尺寸说明](https://developers.openai.com/api/docs/guides/image-generation)。

也可键入 `/draw 画面描述`，使用相同的参数面板。兼容命令 `/image 画面描述` 使用插件默认值，面板会明确标注；更改选项后切换为本次参数。读取设置失败时，新的画图入口会保留描述和附件并拒绝发送，不猜测模型。当前回复结束后才能开始一次性画图，避免混入正在执行的聊天任务。

### 模型切换与助手工具

原有模式继续保留，适合连续专注画图：

在普通对话的模型选择器中选择 **OpenAI 生图 → GPT Image 2.5 Flare · 生图**，然后直接发送画面描述。每条消息生成一张图片，结果作为原生图片附件显示并持久保存。完成后切回 GPT/DeepSeek 等聊天模型即可继续普通任务。

上传 PNG、JPEG 或 WebP 图片后，直接描述修改要求，例如“把蓝色圆形改成红色，保留白色背景、位置和尺寸”。支持同一条消息上传多张参考图（最多 16 张），可按上传顺序描述如何组合。

下一条消息直接说“再把背景改成淡黄色”，会使用最近的结果继续编辑；本次新上传的图片优先。要重新创作、不使用旧图时，输入 **“新建图片：……”** 或 **`/new …`**，也可以新开对话。

也可保持当前聊天模型，对它说“请用 OpenAI 生图工具生成……”或上传图片后说“请用 OpenAI 改图工具修改……”。插件注册 `openai_generate_image` 和 `openai_edit_image`，后者自动读取当前会话的图片，无需提供文件路径。

仅发送当前描述和选定的参考图，不发送整个聊天历史或工作区上下文。连续修改默认使用最近一条带图消息中的图片；想回到更早的版本，请重新上传该版本。在旧版模型切换/助手工具入口，未指定尺寸时编辑按参考图方向选择标准尺寸；描述指定的像素或比例会被识别，工具显式 size 参数优先。需要发送前确认模型、画质、尺寸时，请使用 **画图** 面板。

## 凭据与费用

从 DSH 的凭据服务按名读取现有 `OPENAI_API_KEY`，仅发送到 OpenAI 官方 `/v1/images/generations`（生图）与 `/v1/images/edits`（改图）。参考图通过 DSH 的附件服务读取并以图片数据发送，不把本地文件路径交给 API。不另存 API Key，不读取凭据文件，不向其他站点发送凭据。

默认一张、1024×1024、中画质。实际使用会消耗 OpenAI API 额度。不会自动重试生图请求；会话自动标题只生成本地标题，不调用付费接口。

画图栏明确显示本次模型、画质、尺寸和 1 张的数量。可先选低画质试稿，再按需要选择高画质。费用包括文字输入、参考图输入和图片输出；编辑同样收费。不同模型即使每百万输出 token 单价相同，生成同一画质所用的 token 数也可能不同，因此不显示未经核实的固定单张价，也不把画质选择当成金额上限。以 [OpenAI 官方价格](https://developers.openai.com/api/docs/pricing)和[图片费用估算说明](https://developers.openai.com/api/docs/guides/image-generation#calculating-costs)及账户实际用量为准（核对于 2026-11-05）。

## 安装和配置

推荐使用上方的 Gitee `.tgz` 直链安装。也可以下载源码 ZIP 并解压，然后在 DSH 插件管理器中填入包含 `package.json` 的目录的完整路径；本地目录安装后不要移动或删除该目录。

安装使用 DSH 原生插件管理机制，不修改程序安装包。插件可在“插件”页面停用或卸载。更新时按 DSH 的提示卸载旧版并重新安装，再完整重启。

Config 字段：`apiKeyEnv`、`defaultModel`、`quality`（low/medium/high）、`size`（例如 1024x1024、1536x864，须符合所选模型限制）、`timeoutMs`，以及下方的网络配置。这些字段的默认值见 `cordis.patch.yml`。

本插件不带安装脚本或额外运行时依赖。`peerDependencies` 显式声明需要复用的 DSH 运行时包，这是本地链接安装时解析这些包所必需的。图标为本插件原创 SVG，随代码按 MIT 许可提供。

修改插件 JavaScript 后，正常退出并重新打开 DSH 以加载新模块。首次加载失败的模块也需要重启后重新加载，单独切换启用开关不会清除 Node 的模块缓存。

### 公司代理脚本 / Windows 系统代理（1.2.1）

DSH 0.2.1-rc.5 的后台只从环境变量读取代理，不自动读取 Windows 的 PAC。浏览器能联网，不代表后台生图请求也能联网。插件为 Windows 增加单独的系统网络通道，生图和参考图编辑共用它。

在插件详情的组件配置中：

| 字段 | 作用 |
| --- | --- |
| `networkMode: auto`（默认） | 已设置 DSH 代理环境变量时保留原通道及 `NO_PROXY` 规则；否则 Windows 使用系统代理/PAC，其他系统继续使用 DSH 通道。 |
| `networkMode: system` | 强制使用 Windows 当前用户的系统代理、自动配置脚本和绕过规则。公司使用 PAC 时推荐此项。 |
| `networkMode: host` | 使用原来的 DSH 请求通道，适合已经配置好 DSH 代理的用户。 |
| `proxyUrl`（默认空） | 可选的手动 HTTP 代理地址，例如 `http://127.0.0.1:7890`，仅影响本插件，并优先于 `networkMode`。只填 IT 提供的实际代理主机和端口，不填 PAC 脚本 URL、账号或密码。 |
| `proxyUseDefaultCredentials: false` | 默认不向代理提供 Windows 身份。仅在 IT 要求集成认证时设为 `true`，使用当前 Windows 账号认证所选代理；不把该账号作为 OpenAI 登录凭据。 |

**你使用公司 PAC 时：先确认 Windows 的代理设置中已有公司脚本，再设置 `networkMode` 为 `system`、`proxyUrl` 留空，保存并完整重启 DSH。** 不需要从 PAC 中挑出并写死某一个公司内网 IP。如果脚本只存在于浏览器扩展内，Windows 无法读取它，需要由 IT 配置 Windows 系统代理或提供实际 HTTP 代理地址。

实现通过 Windows 自带 PowerShell 5.1 / .NET Framework 读取系统代理，并在隐藏的临时子进程中发送请求。使用系统证书验证；不改注册表、系统代理、环境变量或 DSH 全局 dispatcher，不关闭证书检查。公司策略禁止 PowerShell 时会明确报错；可选 `host` 并由 IT 配置 DSH 代理，不绕过公司策略。密钥和图片通过进程输入管道传递，不放进命令行或临时文件。

PAC 为目标返回 `DIRECT` 时按该规则直连；选定代理连接失败时不会自动改为直连或重发图片 POST，也不会跟随登录页重定向。PAC 解析由 Windows 实现，插件不下载并自行执行公司脚本。

- **407**：代理认证要求，按公司 IT 的要求处理。
- **建立隧道时 403**：代理拒绝转发，需要 IT 确认是否允许 `api.openai.com:443`。这不等于 API Key 错误。
- **证书错误**：联系 IT 确认公司根证书配置，不关闭 TLS 校验。
- **401 API 响应**：检查 OpenAI API Key；**429** 则进一步区分额度不足和速率限制。
- **超时或连接失败**：检查公司网络、VPN、PAC 可用性及目标访问权限；不要用反复发送收费请求来探测网络。

系统代理读取行为参见 [Microsoft GetSystemWebProxy 文档](https://learn.microsoft.com/en-us/dotnet/api/system.net.webrequest.getsystemwebproxy)。除隔离模拟和 loopback 代理验证外，1.3.0 已通过现有本地 HTTP 代理实际出图；没有改动现有 Windows 代理，也未测试朋友公司的真实 PAC，最终连通性取决于公司网络规则。

## 常见问题

- **提示未配置 OPENAI_API_KEY**：按“首次配置”设置默认 `openai` 提供商。这里需要 OpenAI 官方 API Key。
- **能看到模型但调用失败**：模型列表不代表账号有调用权限或剩余额度；以 OpenAI 的实际报错为准。
- **安装失败或版本不兼容**：保留 DSH 插件页的错误信息，检查网络和 DSH 版本。本版未验证其他 DSH 版本，不建议强行绕过版本检查。
- **旧对话出现 `in-history assistant image` 错误**：1.1.0 的旧图片记录可能不被部分聊天适配器接受，请新建对话并重新上传需要继续修改的图片。1.2.0 的新结果使用兼容的工具图片格式，旧记录不做改写。
- **改图没有保持某些细节**：明确描述只修改什么、哪些内容保持不变；需要回到旧版本时重新上传该图。
- **超时**：插件不会自动重试，请先查看 API 用量再决定是否重新发送。

node --test test/*.test.mjs

网络测试只使用假密钥、独立子进程、`127.0.0.1` 临时监听端口和每次请求独立的代理对象，不访问 OpenAI、不读取或修改机器现有代理。非 Windows 系统跳过 Windows 原生通道测试。
